# 2D 设计计划与路线图

[English](../en/PLAN-2D.md) | [Tiếng Việt](../vi/PLAN-2D.md) | **简体中文**

更新于 **2026 年 10 月 11 日**。本文描述设计目标与验收条件。[README](README.md)、[文明](CIVILIZATIONS.md)、[经济](ECONOMY.md)和[运行时美术](RUNTIME-ART.md)说明已实现内容。列出的目标不等于已经验证通过。

## 产品方向

桌面浏览器单人对 AI RTS，六个文明、三个时代。固定角度 2D 等距美术应在正常视距清楚表达文明、单位职责、建筑用途与动作。玩家可平移和缩放，不旋转镜头。历史灵感跨多个时期，不复原同一年代的战役。

核心规则：四种资源，猎肉归食物，每方 200 人口，一个不可重建的城镇中心，仅当前视野的迷雾，AI 遵守玩家规则，货物交付后入库。双方主城同一模拟步损失则平局。升级时代改变建筑外观并解锁训练，不自动升级现役单位。具体数值由规则文档维护，不在此重复。

## 现状与制作目标

| 范围 | 当前基准                                         | 后续目标                               |
| ---- | ------------------------------------------------ | -------------------------------------- |
| 文明 | 六套可玩阵容，包括大越动员                       | 更多实战平衡和 AI 技能覆盖             |
| 建筑 | 分时代美术，主城可见基础 4/5/6 格，预留区域 8 格 | 完整建造/损坏/摧毁图像                 |
| 单位 | 四个源对角方向，整幅行走/攻击姿势                | 八个独立方向、稳定接地、更完整动作循环 |
| 货物 | 按实际库存选图；大越有分资源图集                 | 所有文明/物品更一致的运动              |
| 移动 | A*、局部避让、编队目的地与脱战命令               | 更强窄道测试及高级阵型                 |
| 地图 | 96×96、三种地形，可读旧 64×64 存档               | 更丰富地形、过渡与清晰战场             |
| UI   | 越/英/简中菜单、HUD、工坊                        | 持续验证无障碍、视口和操作             |
| 性能 | 有限定场景的浏览器/模拟检查                      | 使用真实素材测量 400 单位目标          |

## 美术要求

地面采用 2:1 投影，参考缩放下每格 **64×32 像素**。镜头变换前为 `sx = (x-y) × 32`、`sy = (x+y) × 16`。逻辑地基、图片轮廓和选择区域分别测量，屋顶不应决定寻路阻挡。

保留各文明建筑、材质和装备身份。同用途建筑在六文明中都应可辨识。时代变化保留身份、当前生命、队列和集结点。木栅不会变石墙。当前运行时地基规则优先于旧概念尺寸。

单位目标状态包括待机、行走、工作、蓄力/出击、受击和死亡；相关器械还需装填/部署/收起。稳定锚点、等比例缩放与模拟驱动的攻击时序比帧数更重要。八方向动画是未来制作目标。PNG/WebP 图集应有真实 alpha、留白、已测量帧/锚点、源哈希及权利说明。队色遮罩与建筑损坏图仍待制作。

多余的概念图与用户参考图片已在完成设计参考用途后删除。保留的游戏美术遵循[运行时规范](RUNTIME-ART.md)与[权利记录](RIGHTS-AND-LICENSES.md)。历史研究资料集中在[文明](CIVILIZATIONS.md)文档。

## 技术方向

PixiJS 渲染 WebGL 场景；React 管理菜单/HUD，不为每个 actor 建组件。Web Worker 固定 **20 Hz** 模拟，主线程接收快照并插值。60 FPS 渲染不代表 60 Hz 模拟。

剔除屏外精灵，限制纹理/canvas 缓存与寻路成本，将隐藏敌人排除于绘制和点击检测。存档保留资源、货物、队列、命令、生命、时代、随机种子、AI 和动物/尸体状态，加载后重算视野。性能结论需以真实素材记录 FPS/帧时间、Worker 成本及内存。

## 路线图

1. 维护完整核心：经济、狩猎/交货、建造/训练、时代、迷雾、胜负及存档。
2. 维护六文明、三时代、三地图、三种 UI 语言的一致性。
3. 补齐制作美术，扩展移动/无障碍验证。
4. 按资源预算试验文明平衡，并运行完整配置矩阵。
5. 测量性能，在发行前验证实际生产构建。

## 发行验收

- 正常缩放可辨文明、职责和用途，身份不只依赖队色。
- 美术变更保持地基、训练队列、收货位置与生命；新源图通过裁切/alpha/锚点/哈希验证。
- 选择、追加命令、攻击移动、撤退、坚守、编队、集结及放置在地图/小地图中一致。
- 单位能寻路或报告阻挡，不穿越静态障碍，不无限堆在一个点。
- 交货、死亡、退款、人口、视野及存档有回归覆盖，包括动员与共享尸体。
- 至少 **90 配置：6 玩家文明 × 5 个不同对手 × 3 地图**，另加同文明对战和难度检查。此为目标矩阵，尚非完成的 QA 报告。
- 用真实素材在 **M3 Pro、1080p Medium、总计 400 单位**下测量，目标 60 FPS；记录帧时间、Worker 时间与纹理内存。测量后再设更广设备目标。

在线多人、战役、海军及四队模拟不属于当前原型。发行证据见[验证](VALIDATION.md)。版本化资产清单仍公开保留，旧版 QA 笔记保存在本地。
